# Content-based Bible knowledge graph comparison

Exploratory run 2026-11-06. Source: [Gnosis v0.9.3](https://github.com/spearssoftware/gnosis/releases/tag/v0.9.3), licensed CC BY-SA 4.0; see its SOURCES.md for upstream attribution. Files `people.json` SHA-256 `32dc259628032a583012c5f0b07e1d260d605419d9be66d65a12fc2f1d967f97` and `places.json` SHA-256 `a06494c9b1af61be65ca44fd6e5723c56a54c510227734d2bb2e66ff498b17d6`. Results measure agreement with that graph, not independently verified Biblical or theological truth. The graph has source limitations, missing entries, name disambiguation issues and contested interpretations.

The input is **not the full Bible text**. An automatic converter created 839 short textual facts from the source graph: unique person names and their father, mother, birth place and death place, with names resolved from the source entities. Generated sentences (for example `Isaac's mother was Sarah.`) are graph-derived, not scripture quotations. The complete 839-fact corpus is indexed before answering by both SQLite FTS5 BM25 and XERJ Query-1 CPU model. XERJ stores derived sentences as documents with facts quoting the exact generated value; this is not proof that each claim appears in the Bible verbatim. No test questions or answer keys are indexed. The questions and labels are sampled from the same graph used to build the corpus and are therefore an in-distribution synthetic benchmark rather than an independently authored test.

A deterministic seed sampled 76 father, 40 mother, 29 birth-place and 15 death-place questions, with answers from the graph. They do not mention chapters or verses. For example, `Where was Moses born?`, `Who was Abel's father?`, and `Where did David die?`. Many questions concern obscure people; this is not representative of typical Bible-study queries. They are templated lookups, not semantic reasoning or quotation retrieval.

XERJ receives the open-ended question alone and is marked correct if its final answer matches the graph value after Unicode normalization, case folding and trailing-period removal. Any other ANSWER is wrong; UNKNOWN/UNSUPPORTED/CONFLICT are declines. Seb receives the exact question, four randomly ordered candidate answers and up to five BM25-retrieved graph facts; the correct option is one of those choices. It selects A/B/C/D/unknown. Thus Seb gets multiple-choice candidates while XERJ answers openly: the two tasks are not identical and this may advantage Seb. BM25 uses an exact phrase of the unique subject; both systems rely on the same graph facts. The gold output is never used to choose the BM25 hits. Both systems get graph-derived structured data, so this is not an end-to-end raw Bible extraction test.

Results: XERJ 157 matching answers, 2 differing answers, 1 unsupported; BM25 + Seb 160 matching choices, 0 errors or unknown. No independent scripture verification was done. Example differences: the graph identifies Adam as Abel's father while XERJ returned God, and the graph identifies Timna as Amalek's mother while XERJ returned Eliphaz. `python3 verify.py` checks ordering, counts, response completeness and options. Raw rows and answers are in `questions.json`, `xerj-results.jsonl`, and `seb-{0,1}.json`; `summary.json` records the outputs.

Median XERJ client wall time 226.8 ms; median BM25 retrieval 0.0119 ms and median Seb per-item API timing 65.6 ms (batches with up to four concurrent calls; timing is not matched end-to-end). Seb usage was 30,185 input tokens and 633,885 cost-nanos = $0.000633885 for 160, or $0.00396178125 per 1,000 calls, excluding BM25 compute and hosting. Server CPU increased 143.92 seconds over 160 XERJ calls, including background work; at the article's $0.03625/vCPU-hour rate this projects to $0.0090575/1,000. The CPU was measured on an Apple Mac, not an AWS instance, so this is not an AWS bill. Both figures exclude idle capacity, storage, and other infrastructure. Multiplication to 100K/1M/10M assumes identical workload and pricing; it is not a throughput test.

XERJ fact/doc bulk commit took 147.8 ms wall (excludes client construction/serialization); BM25 insertion and commit took 2.19 ms wall on prebuilt facts. Fact construction and downloads excluded, and index CPU costs were not measured. These are 839 graph facts, not the earlier full Bible chapter index. Model loading excluded.

Reproduce: download `people.json` and `places.json` from the pinned release to `../data/`, verify the hashes, start a fresh rc.101 CPU XERJ node at loopback port 19291, then run `python3 bench.py prepare`, `python3 bench.py index`, `python3 bench.py ask`; use a fresh `facts.sqlite` and empty `kg` namespace. Send the 160 `state` fields in batches of 100 and 60 to Seb `seb_batch_decide` pinned to v2, with choice criteria A, B, C, D, unknown and instructions: `Use only the evidence to answer the question. Select the letter corresponding to the supported option; choose unknown if the evidence is insufficient.` The shared criteria are `A: The answer is option A.` through D and `unknown: The evidence does not identify an answer.`
